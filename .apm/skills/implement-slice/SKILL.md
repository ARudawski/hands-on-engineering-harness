# Implement a slice

Read applicable guidance, supplied scope/ACs and existing task records. Resolve material ambiguity; a small task needs no separate specification. Preserve unrelated edits and establish a reproducible comparison before changing source: available VCS state, or before-content/path inventory with retained after-state evidence including added/deleted paths.

Implement only the authorized increment. Use a failing then passing behavior check where a suitable seam exists; otherwise run relevant checks and state the gap. Reuse valid green evidence for behavior-preserving changes. Fix causes, follow applicable conventions and update affected documentation within scope. Agree scope/AC changes; do not reopen accepted limitations without materially changed evidence. After failure, change the cause/approach or report the blocker; bound justified retries.

Reconcile actual changes, comparison, AC results/gaps and next action in the existing project-root `.tmp/<task>/` records when needed; keep ordinary notes Markdown and index navigation separate. Report the assessed revision and distinguish implemented, verified and inferred results.

Return results to the parent workflow and its approval/review gate. Standalone, report scoped completion/gaps and stop; do not start `deliver-task`, dispatch extra stages, commit, push or publish without that action's authorization.
