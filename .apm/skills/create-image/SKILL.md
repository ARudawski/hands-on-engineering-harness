# Create an image

## Work within the task

For a direct invocation, select the image type and use General delivery in [deliver-task][delivery] once for planning, authorization, records and handoff. The initial creation request authorizes plan preparation, not execution; reuse an actual prior scoped execution grant when one exists. Do not infer that grant from the initial request's wording or a local-only destination.

[delivery]: ../deliver-task/SKILL.md

When a parent already selected this type, apply the guidance below at its current stage and within its exact grant. Reuse its record, brief and valid results; do not restart delivery or routing. Return the artifact, checks and remaining gaps to the parent. A maintained software change remains with the parent's engineering workflow; a disposable rendering script does not make an image request software work.

## Establish the brief and execution path

Capture intended use, requested content or change, hard constraints, preferences, reference roles and relevant output requirements. Reuse supplied information and ask only for material missing decisions. For edits, identify the original and protected elements; for a set, identify its common reference. Do not invent exact copy, source data or brand rules.

Choose generation, reference-guided generation, editing or deterministic rendering using actual available capabilities. Load the applicable runtime skill/tool guidance and use supported inputs and parameters. Confirm the path can receive required references, expose the result for inspection and deliver the artifact. A product name is not evidence of a generator. If a required capability or reference is missing, retain the brief and name the dependency; a prompt or placeholder does not complete an image request.

Distinguish the visual's purpose:

- **Expressive visuals:** art, logos and posters. Explore meaningful differences in composition, silhouette, pose or visual language; retain details needed to judge the idea.
- **Information graphics:** charts, diagrams and infographics. Preserve authoritative facts, values, units, labels and relationships while exploring valid encodings, axes or layouts. Explain consequential scale/encoding choices; do not make misleading comparisons or invent missing data. Use deterministic rendering or finishing when exact text, data or geometry requires it. Decorative generation may be combined with that path.

## Explore until a direction is chosen

For an unresolved direction, present up to four deliberately different rough candidates per round, labelled with a short comparison. Use outlines or simplified rendering where suitable; include colour, typography or other crucial details when needed for the choice. Four is a ceiling, not a quota. Use supported lower-effort controls when appropriate; rough appearance alone does not prove lower cost or latency.

Wait for the user to select, combine identified elements or reject the set unless they explicitly delegated selection. Treat this as a creative decision within the authorized task, not another execution-approval gate. Resolve an ambiguous combination only when material, then record one selected baseline and its defining features. Further exploration rounds use the user's feedback within the task's effort allowance.

Once selected, stop producing alternative direction sets. Increase fidelity and revise within the chosen direction. A precise edit or an already chosen direction skips exploration. Routine feedback does not reopen it. If the chosen approach proves infeasible, explain the issue and ask whether to reopen; only the user's decision reopens exploration.

## Inspect, refine and deliver

Inspect the actual result against the brief at the appropriate fidelity. Sketches can defer finish details; final output cannot. Check hard requirements first, then fitness for use and technical properties such as dimensions, format, transparency and legibility when relevant. Compare edits with the original and chosen baseline; compare related assets both with their common reference and each other. For exact pixel preservation, use a compatible editing/compositing path and verify the protected region rather than trusting a preservation prompt.

Revise for a named defect or requested change and recheck what must remain intact. Keep the original and a usable prior version. Stop on success, a material capability/decision gap, exhausted agreed effort or repeated lack of improvement; report the best result and outstanding issue instead of silently changing direction or polishing indefinitely.

Show or link the actual selected artifact and satisfy requested export/destination requirements. Verify accessibility and required properties before reporting delivery. Distinguish agent-checked delivery from actual user acceptance and identify checks that remain uncertain.

Retain enough in the existing record to resume: brief, reference identities, candidates needed for the choice, selected direction, current artifact, relevant exposed settings, consequential checks and next action. Resume from that selected version without reopening settled decisions. Traceability does not guarantee reproduction of identical pixels.
